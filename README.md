# כרטיס שחקן פאדל

אבטיפוס סטטי (HTML/CSS/JS) לכרטיס שחקן בעברית, מובייל-פרסט. שאלון קביעת רמה, תמונה, פרטנר קבוע מהמאגר, וקישור לשיתוף — כרטיס אישי או כרטיס זוג. שדות רשות: אזור, מגרשים קבועים, תדירות, ותק, סגנון וחוזקות. הדירוג בכרטיס מגיע רק מהשאלון (למשל B2 · 4.0). בעל הכרטיס יכול להעתיק את הקישור או לשתף אותו לוואטסאפ מהמכשיר שבו נוצר הכרטיס; מארגן שפותח כרטיס של מישהו אחר לא רואה את כפתורי השיתוף. במסך הכרטיס כפתור «בית» בראש המסך מחזיר לדף הבית.

## הרצה מקומית

```bash
python3 -m http.server 8765 --directory /workspace/padel-card-v20
```

פתיחה: http://127.0.0.1:8765/

הנתונים נשמרים ב-localStorage. כרטיס לשיתוף מקודד בכתובת (`#/p/...` ליחיד, `#/pair/...` לזוג). תמונות וסרטונים מועלים ל-Cloudinary (presets: `padel_card_photos`, `padel_card_videos`) והקישור המשותף שומר רק את כתובת הענן. כרטיסים ישנים עם תמונת data URL ממשיכים להופיע, ובעל הכרטיס רואה בקשה להעלות מחדש תמונה חדה לענן. אחרי העלאת סרטון, השחקן מסמן את עצמו ועיגול עוקב אחריו לאורך הסרטון. אם הזיהוי האוטומטי לא זמין אפשר ללחוץ ידנית על עצמכם בתמונה — ננסה לעקוב לפי הנקודה והצבע, ואם לא נוכל יישמר סימון "אני" בתחילת הסרטון (לא לכל אורך הסרטון).

לא לפרוס לציבור — זה אבטיפוס בלבד.

הנכסים הסטטיים נטענים מתיקייה `v20/` (למשל `v20/app.js`) כדי לעקוף את מטמון ה-CDN של Render, שמתעלם ממחרוזת `?v=N`. אחרי עדכון, מעתיקים את הקבצים לתיקיית גרסה חדשה ומעדכנים את `index.html`.

## פריסה ציבורית (Render)

האתר הוא סטטי (HTML/CSS/JS). כדי לפרסם קישור חי ב-Render צריך מאגר Git ש-Render יכול לשכפל.

כרגע אין מאגר מתאים בחשבון GitHub (`talgaled-del`): המאגר היחיד הוא `comicst` (פרויקט אחר, לא לגעת),
ואין כלי שיוצר מאגר GitHub חדש מהסוכן. קריאה ל-`create_static_site` ב-Render נכשלה עם:

`400: repo is required when using service type: static_site`

### מה צריך לעשות
1. ב-GitHub, צרו מאגר ריק חדש (מומלץ ציבורי) בשם למשל `padel-card` תחת המשתמש `talgaled-del`.
2. שלחו את כתובת המאגר (למשל `https://github.com/talgaled-del/padel-card`).
3. נדחוף את הקבצים מ-`/workspace/padel-card-v20/` ונפרוס Static Site ב-Render לפי `render.yaml`
   (`buildCommand: true`, `staticPublishPath: ./`).

דמו אחרי הפריסה:
- כרטיס יחיד: `{URL}/#/demo/michal`
- כרטיס זוג: `{URL}/#/demo/pair`

## AI Rating (v12)

בעל הכרטיס לוחץ «קבל AI Rating» ליד הסרטונים. השרת (`server/`) מוריד את הסרטון מ-Cloudinary, שולח אותו ל-Gemini יחד עם תיאור השחקן המסומן (חצי המגרש, צד, מיקומים לאורך הסרטון וצבע בגדים), ומחזיר רמה בסולם האותיות, ביטחון, הסבר קצר וציוני משנה. התוצאה נשמרת בכרטיס ובקישור המשותף (`ai` ב-hash).

- `POST /api/ai-rating` — `{ videoUrl, track, cardId }` או `{ videos: [{ videoUrl, track | trackUrl, duration, appearance }], cardId, profile }`
- `GET /healthz`
- משתני סביבה: `GEMINI_API_KEY` (חובה), `GEMINI_MODEL` (ברירת מחדל `gemini-3.8-flash`), `ALLOWED_ORIGINS`, `MOCK_AI=1` לבדיקות, `RATE_PER_HOUR`/`RATE_PER_DAY`/`MAX_CONCURRENT`.
- הרצה מקומית במצב בדיקה: `cd server && MOCK_AI=1 EXTRA_VIDEO_HOSTS=127.0.0.1:18767 PORT=8787 node server.js`, ואז `node scripts/verify-v12.mjs`.
- קריאה אמיתית אחת מקובץ מקומי: `GEMINI_API_KEY=... node server/try-local.js video.mp4 track.json 30 black`.
- בצד הלקוח כתובת השרת מוגדרת ב-`AI_API` בראש `app.js` (`https://padel-card-api.onrender.com`; ב-localhost `http://127.0.0.1:8787`; אפשר לעקוף עם `localStorage["padelCard.apiBase"]`).

## v13

- **ניתוח לפי סרטון:** כל סרטון נשלח בבקשה נפרדת (`perVideo: true`), אחד אחרי השני, והתוצאה נשמרת על הסרטון (`v.ai`, ובקישור `a`) עם מפתח של הסרטון והסימון. סרטון שכבר נותח לא נשלח שוב; סימון מחדש מבטל רק אותו. תוצאה כללית מ-v12 משויכת לסרטונים הראשונים לפי מספר הסרטונים שנותחו אז.
- **שילוב דטרמיניסטי (בצד הלקוח):** משקל = שניות (מינימום 10) × ביטחון (1/2/3). רמה = ממוצע משוקלל של המיקום בסולם, מעוגל. ציוני משנה = ממוצע משוקלל מהסרטונים שבהם נצפו. ביטחון = ממוצע משוקלל, מוגבל לפי סך הזמן (פחות מ-2 דק׳ נמוך, פחות מ-5 דק׳ לכל היותר בינוני), ויורד דרגה אם יש פער של 3 רמות ומעלה בין הסרטונים. סרטון שנמחק יוצא מהחישוב.
- **פס התקדמות:** הערכה לפי זמן (2.7 שניות לכל שנייה של סרטון + 8 שניות), עד 95% עד שמגיעה תשובה, ושלב «מעיר את השרת…».
- **תג הרמה למעלה:** פער של רמה אחת בין השאלון ל-AI מוצג כטווח (למשל C1-B2). פער גדול יותר: נשאלים פעם אחת לכל צירוף רמות (`profile.lr`).
- **דף הבית:** «איך זה עובד». **סרטונים בכרטיס:** אזור מתקפל, סגור כברירת מחדל, זוכר את המצב בסשן.
- בדיקה: `node scripts/verify-v13.mjs` (שרת mock, ראו הערה בראש הקובץ).

### הגדרות שעדיין צריך ב-Supabase (אם לא הושלמו)

1. **Authentication → URL Configuration**
   - **Site URL:** `https://padel-card.onrender.com`
   - **Redirect URLs:** `https://padel-card.onrender.com`, `https://padel-card.onrender.com/**`, ולבדיקות מקומיות `http://127.0.0.1:8765` / `http://localhost:8765` (או הפורט שבו מריצים).
2. **Email OTP:** Authentication → Providers → Email — הספק מופעל. מומלץ לכבות Confirm email באבטיפוס. בתבנית המייל (Magic Link / OTP) חייב להופיע `{{ .Token }}`, לא רק קישור.
3. **Google:** ב-Google Cloud צרו OAuth client (Web application). Authorized JavaScript origins: `https://padel-card.onrender.com` ו-`http://127.0.0.1:8765`. Authorized redirect URI חייב להיות של Supabase: `https://ehcsbtbcelfoxfgraytl.supabase.co/auth/v1/callback`. ב-Supabase: Authentication → Providers → Google — הדביקו Client ID ו-Secret.

## v15

הכרטיס קשור לחשבון המחובר. אחרי התחברות (וגם בטעינה עם סשן קיים) נטען הכרטיס מטבלת `public.cards` ב-Supabase. אם אין עדיין שורה אבל יש כרטיס במכשיר (`padelCard.v2`), הוא מועלה אוטומטית לחשבון — כך הכרטיס שטל בנה עד כה עובר לחשבון כשיתחבר במכשיר שבו הוא שמור. כל שמירה (פרופיל, שאלון, סרטונים, AI, החלטת תג) מעדכנת את השורה בענן (עם השהייה קצרה). מזהה הכרטיס נשמר כדי שקישורי השיתוף הקיימים ימשיכו לעבוד.

- **צפייה ועריכה של הכרטיס שלי** רק אחרי התחברות. במסך הבית, בלי התחברות, מופיע מסך ההתחברות («התחברו כדי ליצור ולשמור את כרטיס השחקן שלכם»).
- **קישורי שיתוף** (`#/p/...`, `#/pair/...`, כרטיסי דוגמה) נשארים פתוחים לכולם בלי התחברות, כולל שתי שורות הדירוג.
- אם יש כרטיס בענן וכרטיס מקומי שונה, הענן גובר, והעותק המקומי נשמר ב-`padelCard.v2.backup`. התנתקות מחזירה למסך ההתחברות ולא מוחקת את הנתונים.
- הנכסים הסטטיים ב-`v15/`. בדיקות: `node scripts/verify-v15.mjs` (רגרסיית v13/v14 אחרי התחברות), `node scripts/verify-v15-auth.mjs` (שער התחברות + מבקר), `node scripts/verify-v15-sync.mjs` (סיבוב אמיתי מול Supabase עם משתמש בדיקה שנמחק בסוף).

## v20

תיקון סנכרון כרטיס + בקשות דירוג כוכב.

בגרסאות הקודמות, אם מישהו התחבר במכשיר שבו כבר היה שמור כרטיס של חשבון אחר, הכרטיס המקומי הועלה אוטומטית לחשבון החדש. מעכשיו כרטיס מקומי שכבר משויך לחשבון אחר לא נטען ולא מועלה. במסך הבית ובסרגל העליון מוצג האימייל של החשבון המחובר, ומוסמך דירוג רואה גם תג «מוסמך דירוג ⭐». אי אפשר לשייך למוסמך אימייל שמופיע ברשימת המנהלים; אם לאימייל כבר יש חשבון או כרטיס, המנהל מקבל אזהרה.

שחקן יכול לבקש דירוג כוכב ממוסמך שיש לו אימייל משויך («בקש דירוג כוכב ⭐» בבית ובכרטיס). מוסמכים בלי אימייל מוצגים כ«בקרוב». הבקשות נשמרות ב־`public.rating_requests` (ממתין / דורג / נדחה / בוטל), עם מגבלה של בקשה ממתינה אחת לכל מוסמך ולכל כרטיס, ועד שלוש בקשות ממתינות למשתמש. המוסמך רואה תיבת דואר בבית, יכול לדרג או לדחות; השחקן רואה את הסטטוס ויכול לבטל. קישור ישיר `#/rate/<מזהה-בקשה>` נפתח אחרי התחברות. דירוג ישיר מקישור שיתוף נשאר כמו ב־v19. בקונסולת המנהל, בלשונית «מוסמכים», מופיעות הבקשות עם מונים.

מייל למוסמך נשלח מצד השרת בלבד, דרך Edge Function בשם `notify-rating-request` (Resend, מ־`login@padelcard.app`). בדיקות לא שולחות למוסמכים אמיתיים.

הנכסים הסטטיים ב־`v22/`. (v20 נשאר מתועד למעלה.) בדיקה: `node scripts/verify-v20-requests.mjs`. אין לפרוס את האתר הסטטי מהחבילה בלי בדיקת טל; ה־API ב־Render לא השתנה.

## v21

תיקון בעלות כרטיס כשיש אותו מזהה אצל שני חשבונות (כרטיס ששוכפל בטעות), והסתרה בבורר של המוסמך שמחובר כרגע («זה החשבון המחובר»). מזהה כרטיס (`private.card_id_of`) יכול להיות שייך למשתמש אחד בלבד — אינדקס ייחודי וטריגר דוחים upsert לחשבון אחר. הלקוח לא שומר כרטיס שכבר משויך למשתמש אחר, ולא מאחד כרטיס מקומי של חשבון קודם אחרי החלפת התחברות. חשבון מחובר בלי כרטיס רואה «צור כרטיס חדש».

במסך הבית, מוסמך עם בקשות ממתינות רואה באנר בולט «יש לך N בקשות דירוג ממתינות ⭐» וסימון אדום על התג בסרגל. לחיצה מעבירה לתיבת הבקשות. המונה מתרענן כשחוזרים לחלון.

אחרי שליחת בקשה מוצג מצב לפי תוצאת Resend: «✉️ נשלח מייל ל<שם המוסמך>» ו«הבקשה ממתינה לדירוג», או «הבקשה נשמרה, אך המייל לא נשלח» עם «נסה שוב». ברשימת הבקשות של השחקן מופיע «מייל נשלח · <שעה>».

גיליון הדירוג הוא תפריט רמות + כפתור «אשר» (בלי אפשרות דחייה בממשק השחקן/התיבה). אחרי דירוג נשלח מייל «<מוסמך> דירג אותך», ובאפליקציה באנר «קיבלת דירוג מוסמך חדש» שנעלם אחרי צפייה.

בכרטיס: «דירוג שאלון», «דירוג AI», «דירוג מוסמך» (חציון אם יש כמה; בלי כוכב), ו«דירוג משוקלל» מודגש — 50% מוסמך, 30% AI, 20% שאלון, מנורמל לפי מה שקיים ומעוגל לרמה הקרובה. הרמה ליד התמונה היא המשוקללת. הכפתור: «בקש דירוג ממוסמך».

בדיקה: `node scripts/verify-v21.mjs`. אין לפרוס את האתר הסטטי מהחבילה בלי בדיקת טל.


## v22

כרטיס מוסמך, הזמנות חד־פעמיות, ומדריך מוסמכים ציבורי.

מוסמך (שורה ב־`certified_raters` שמקושרת לחשבון) מקבל פרופיל מקצועי נוסף לכרטיס השחקן: מועדונים, עיר ואזור, שנות ניסיון, הסמכה או קורס (לא חובה), קהל יעד (ילדים / מתחילים / מתקדמים / תחרותיים), ביו קצר, ותמונה (או תמונת כרטיס השחקן). פרטי קשר לשיעורים מוצגים רק אם בחרו לפרסם אותם. אם המוסמך גם שחקן פעיל, הכרטיס מציג את הדירוג המשוקלל ומקשר לכרטיס השחקן. תג «מוסמך». עריכה מ«הפרופיל שלי כמוסמך» במסך הבית של המוסמך. גישה לטבלה `public.certified_rater_profiles` היא RPC בלבד: המוסמך מעדכן את השורה שלו, המנהל יכול לערוך, והציבור קורא פרופילים מלאים בלבד.

שיתוף ציבורי: `#/coach/<id>`. מדריך: `#/coaches` («המוסמכים שלנו») — מוסמכים פעילים עם פרופיל מלא. בבורר בקשת הדירוג מוצגות כרטיסיות עם תמונה, שם, מועדונים וניסיון, עם חיפוש לפי שם או מועדון.

בלשונית «מוסמכים» במנהל: «צור קישור הזמנה» — אסימון חד־פעמי (נשמר מגובב, תוקף 30 יום), כתובת `https://padelcard.app/#/invite/<token>`. המוזמן מתחבר באימייל או בגוגל, ו־RPC מאובטח (`claim_rater_invite`) קושר את החשבון לשורת המוסמך (דוחה אסימון משומש או שפג, ואימייל מנהל). אחר כך משלימים את הפרופיל. כפתור העתקה עם הודעת וואטסאפ מוכנה, מותאמת לשם. תבנית כללית: `coach-invite-message.txt`.

מיגרציות: `v22_certified_rater_profiles_and_invites`, `v22_fix_coach_public_json_card_id`. הנכסים הסטטיים ב־`v22/`. בדיקה: `node scripts/verify-v22-coaches.mjs`. אין לפרוס את האתר הסטטי מהחבילה בלי בדיקת טל.


## v23

תיקון הזנת קוד OTP ב־iOS Safari, והגבלת בקשת דירוג מוסמך לפעם בשלושה חודשים.

מסך «הזינו את הקוד» משתמש עכשיו בשדה `<input>` אחד אמיתי (`autocomplete="one-time-code"`, `inputmode="numeric"`, `pattern="[0-9]*"`, `maxlength=6`, `name="otp"`) בתוך טופס, עם מיקוד אוטומטי. שש התיבות נשארות עיצוב בלבד מעל השדה (השדה שקוף אבל לא `display:none`, כדי ש־iOS יוכל להציע את הקוד מעל המקלדת המספרית). אחרי 6 ספרות — הקלדה, הדבקה או מילוי אוטומטי — הטופס נשלח לבד. «הדבק קוד» ו־backspace עובדים, והספרות מוזנות משמאל לימין.

תבנית מייל ה־OTP (Magic Link / Confirmation) עודכנה: הנושא הוא `קוד הכניסה שלך ל-Padel Card: {{ .Token }}`, והגוף שומר על העיצוב הקיים עם הכותרת «הקוד שלך» והקוד בגדול. השולח נשאר `login@padelcard.app`.

בקשת דירוג מוסמך: אחרי בקשה (לכל מוסמך, לפי `created_at` האחרון של המבקש) אי אפשר לבקש שוב במשך 3 חודשים. זה נאכף ב־`create_rating_request`, והממשק משבית את «בקש דירוג ממוסמך» ומציג הסבר קצר עם תאריך הבקשה הבאה (`dd/mm/yyyy`). מיגרציה: `v23_rating_request_cooldown`.

הנכסים הסטטיים ב־`v23/`. בדיקה: `node scripts/verify-v23.mjs`. אין לפרוס את האתר הסטטי מהחבילה בלי בדיקת טל.

## v24

כרטיס המוסמך עומד בפני עצמו, בלי כרטיס שחקן מקושר.

מוסמך דירוג פעיל לא מקבל כרטיס שחקן: במסך הבית מוסתרים «צור כרטיס», עריכת כרטיס, «הכרטיס שלי» ובקשת דירוג. הבית שלו הוא כרטיס המוסמך, בקשות דירוג ממתינות, ועורך הפרופיל («הפרופיל שלי כמוסמך»). אחרי מימוש הזמנה מגיעים רק לעורך הפרופיל. בשרת, טריגר על `public.cards` דוחה insert (או עדכון `user_id`) למשתמש שמחובר למוסמך פעיל, עם השגיאה `certified raters cannot have a player card`. כרטיסים קיימים לא נמחקים. מנהלים אינם מוסמכים, ולכן כרטיס השחקן של המנהל נשאר.

בפרופיל המוסמך נוספו «הרמה שלי» (רמות האותיות הקיימות: D2 עד A1) ו«דירוג ארצי» (לא חובה). שניהם מוצגים בכרטיס הציבורי `#/coach/<id>`, במדריך «המוסמכים שלנו» ובבורר בקשת הדירוג. התמונה מועלית ישירות בעורך, בלי נפילה לתמונת כרטיס שחקן. ה־JSON הציבורי כבר לא כולל קישור לכרטיס שחקן, דירוג משוקלל של שחקן, או `show_player_card`.

מיגרציה: `v24_coach_profile_standalone`. הנכסים הסטטיים ב־`v24/`. בדיקה: `node scripts/verify-v24.mjs`. אין לפרוס את האתר הסטטי מהחבילה בלי בדיקת טל.

## v25

מוסמך מחובר לא רואה את שאר המוסמכים. כפתור «המוסמכים שלנו» מוסתר בבית, ופתיחה ישירה של `#/coaches` מחזירה אותו לבית. כפתור «חזרה» מכרטיס מוסמך מחזיר את המוסמך לבית (לא למדריך). רשימת כל המוסמכים נשארת בלשונית «מוסמכים» של המנהל. שחקנים עדיין בוחרים מוסמך בבורר בקשת הדירוג.

המדריך הציבורי `#/coaches` נשאר פתוח לשחקנים ולאורחים — אין בזה סתירה, כי השחקנים צריכים להכיר מוסמכים, והמוסמך עצמו לא צריך לראות את העמיתים.

שיתוף כרטיס המוסמך: בכרטיס במסך הבית של המוסמך, וב־`#/coach/<id>` כשהבעלים צופה בו, מופיעים «העתק קישור» (מעתיק `https://padelcard.app/#/coach/<id>` באתר החי, עם הודעה «הקישור הועתק») ו«שלח בווטסאפ» (`https://wa.me/?text=` עם «כרטיס המוסמך שלי בפאדל ⭐» והקישור). כש־`navigator.share` זמין במובייל, נוסף גם כפתור «שתף», כמו בנפילת השיתוף של כרטיס השחקן.

תגיות Open Graph נוספו ל־`index.html` יחד עם `og-cover.png`. לכרטיס השחקן לא היה עד עכשיו תצוגת OG ייחודית (הקישורים מבוססי hash, והסורקים לא קוראים את החלק אחרי `#`). אותה מגבלה חלה על כרטיס המוסמך; התגיות האתר-רחבות נותנות תצוגה ממותגת לכל קישור של Padel Card.

הנכסים הסטטיים ב־`v25/`. בדיקה: `node scripts/verify-v25.mjs`. אין לפרוס את האתר הסטטי מהחבילה בלי בדיקת טל.
